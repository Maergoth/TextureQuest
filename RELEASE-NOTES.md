TextureQuest 1.4.1 explains both installation modes and adds a hover info icon beside each choice. Replace PAK files is recommended because it avoids injecting a runtime component into the game process. Replace PAK files and Background texture loader are exclusive modes; an existing background-mode selection is retained.

Replace PAK files copies verified replacement archives into the game's paks folder, where the game loads them directly. It needs no background watcher or injected loader. The tradeoff is that game archives are changed: patches can overwrite the pack, and the official patcher's file validation is needed to restore stock files.

Background texture loader prepares private archives from verified texture downloads and stock game files. A per-user startup watcher detects ordinary future launches of the selected EverQuest2.exe and loads a DLL that redirects selected file reads inside the client. It leaves game PAKs, settings and shortcuts unchanged. The tradeoffs are a required private cache and available portable app/watcher, runtime injection, limited client coverage and manual refresh when a patch changes game archives or indexes. Wait for installation to report ready before launching normally. An initial in-world test succeeded on one exact Windows EverQuest II Origins client; this is not universal client or launch-path coverage.

Patch with the official launcher first and close every EQ2 client and the launcher before installation. Existing PAK replacement users must restore stock game archives with the official patcher's file validation before choosing background mode. Verified saved texture downloads are reused. Keep the portable app and its data folder in place after installation.

Uninstalling the background loader stops its startup watcher and future attachments. Already attached clients retain the loader until they close. There is no instant original/upscaled switch. Uninstall the loader and close all active clients before changing modes, applying an app update or clearing the app cache; the current app guards refuse update/cache actions while loader ownership is active.

Known limitations: automatic post-patch private-cache refresh is unfinished. If a patch changes game archives or indexes, uninstall and reinstall the background loader to refresh that cache. An EXE-only patch does not itself alter texture content, but new client builds still need compatibility validation. Other EQ2 versions, all launch paths and future game patches have not been fully tested. PAK replacement may need reinstalling after a game patch. The recommendation describes the loading method and does not establish account-policy compliance; the existing warning about possible account consequences still applies.

Textures remain version 1.2.3: the same 24,693 textures across 310 complete archives, with every archive byte identity and download URL unchanged. The 312 recovered Maj'Dul/Desert of Flames textures, Ratonga repair, selected 4K textures, effects, alpha maps and other prior updates remain included. The new app bundles the existing 1.3.7 manifest. Additional missed-texture generation is unfinished and is not included in this app release. No game GPU setting, texture-generation recipe or generation model changes are part of this release.

Texture downloads, installation and app updates remain separate actions. Download / Resume prepares verified texture downloads; Install TextureQuest applies PAK replacements, and Install background loader prepares background mode. Get app update downloads, verifies and replaces the managed app files, then restarts TextureQuest while preserving the data folder, saved downloads and installation history. App 1.3.4 and earlier need one final manual upgrade: close the old app, extract this release into a new writable folder outside the game and move data alongside the new TextureQuest.exe. Keep the extracted files together.

The repository includes the exact reviewed portable loader payload under sideload-runtime and the corresponding native C++ source under sideload-native. Build the app with: python build_installer.py --manifest release-manifest-1.3.7.json --version 1.4.1 --loader-runtime-dir sideload-runtime. Rebuilt binaries are not promised to have identical bytes.
